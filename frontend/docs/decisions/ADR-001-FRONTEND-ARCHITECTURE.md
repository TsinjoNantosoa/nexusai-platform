# ADR-001: standalone Vite SPA

Date: 2026-11-25
Status: Accepted for Phase 1

## Decision

Run NexusAI as a standard Vite React SPA with TanStack Router file-based routes. Use the browser router and a single client-side QueryClient. Keep the future FastAPI boundary same-origin under `/api/v1`, with Vite proxying `/api` during local development.

## Context

The imported application depended on TanStack Start, Nitro, Lovable build configuration, and SSR-specific entry points. The target backend is a separate FastAPI service. The product requirements prioritize portable hosting, stable route URLs, mock/API separation, and a controlled PWA over server-rendered frontend output.

## Consequences

- Hosting must rewrite application routes to `index.html`.
- There is no SSR data preloading or server request context in the frontend.
- Authentication and financial authority remain backend concerns.
- The PWA worker is generated by Vite and is not enabled during development.
- A future SSR requirement would require a new ADR and explicit cookie, QueryClient, and hydration tests.
